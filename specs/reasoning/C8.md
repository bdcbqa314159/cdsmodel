# C8 — the add-in in real Excel

**Status: NOT YET RUN.** No evidence exists for the add-in in Excel.

C8 of `specs/03_xll.md` is the one criterion CI cannot reach: an XLL only truly
runs inside Excel, interactively, on Windows. Everything else about the add-in
is tested without it — 41 tests over `xl/core`, covering marshalling, the
registration table, dispatch, the handle registry and both signature forms —
but "it loads and registers in Excel" is not among them.

This file is the only place that evidence can live. **While it says NOT YET
RUN, the add-in is unverified in Excel and should be described that way.**

## How to run it

    cmake --preset release                       # with the SDK in xlsdk/
    cmake --build --preset release --target cdsmodel_xll
    python tools/gen_xll_workbook.py             # writes tests/xll/smoke.xlsx

Load `cdsmodel.xll` in 64-bit Excel, open the workbook, let it recalculate.

### Expected values, computed from the library

These come from `tools/gen_xll_workbook.py`, which builds a program against the
same library the add-in links — no number here was typed by hand.

| case | expected |
|---|---|
| 5y, 100bp, ACT/360 | -0.018102268357 |
| 10y, 250bp | -0.151384404732 |
| 5y mid-period, dirty | -0.017992198749 |
| 5y mid-period, clean | -0.016964420971 |

The last two differ by 0.001027778, which is 37 days at 1% on ACT/360 — the
accrued interest. Two earlier versions of that case returned identical numbers
for clean and dirty, once because the trade started on the valuation date and
once because the valuation date landed on a coupon date. Both are dates where
accrual is zero by definition, so the case could not fail. It is now valued
mid-period on purpose.
## What to read in the sheet

The workbook is self-contained -- it builds its own curves, so there is nothing
to fill in.

| cell | what it tells you |
|---|---|
| `B9` | the add-in loaded and dispatched at all |
| `B6` / `B7` | the curve builders worked. A handle like `USD#1` is success; **text is the diagnostic** and worth recording verbatim |
| column J | each price against the value the C++ library computed: PASS, or FAIL with the difference |
| column K | the 16-argument and 5-argument forms against each other: SAME, or DIFFER with the gap |

Column K is C9 checked inside Excel. Both forms read into the same four structs
and then run one code path, so a test already proves they agree bitwise off
Excel -- but that test cannot see a marshalling difference between the two
argument shapes, and this column can.

**A partial result is still worth recording.** If `B6` holds text, the add-in
loaded, registered, dispatched and returned a readable message rather than
`#VALUE!` -- which is C1, C2 and C3 demonstrated in the real host. Copy the
text; it names the field and the value.
